LEG-199 · Proposed · Awaiting approval

Server-owned OAuth.
Explicit tool grants.

The phone displays consent. Legato receives the callback, exchanges the code and keeps credentials. Agents use the host broker.

The phone browser must reach the callback. The provider redirects that browser; it does not call Legato itself.

First release

Remote Streamable HTTP and local controlled agents. No worker forwarding, subprocess launches or hosted relay.

What binds the callback?

A ten-minute transaction records operator authority, instance, connection generation, exact issuer, resource, registration and redirect. State is single-use. The verifier remains sealed server-side.

What if the external browser has no Legato login?

It can settle only that transaction. The original UI, or another authenticated device, resumes from Settings and confirms the account/resource. The callback cannot activate tools.

When can two agents use it?

After activation and explicit grants. Each call checks execution, task, repository, tool, operation and resource. No agent receives an upstream token or starts its own OAuth login.

What happens on failure?

Denial, cancellation, expiry and interrupted exchange have distinct states. Concurrent attempts cannot replace newer credentials. Disconnect blocks new dispatch and late activation. Ambiguous mutations are not retried automatically.

Required approval choices

  1. HTTP upstreams and local agents first.
  2. Explicit root HTTPS web.public_url for callback origin.
  3. Authenticated account/resource confirmation after callback.
  4. Explicit agent reload for additions, immediate denial for revocation.
Reachability is not universal

LAN/VPN callbacks can work only when the phone browser reaches them, trusts TLS, and the provider permits the exact redirect. App certificate pinning does not establish browser trust.

CIMD separately requires provider access to its HTTPS metadata. Pre-registration or DCR is an alternative only where supported. Current MCP deprecates DCR.

If the phone cannot reach Legato, direct callback cannot complete. Device authorization requires provider support. A relay would introduce a separate trust and availability dependency. Neither is in this first release.

Estimate and verification

Six proposed Large phases: 48 points, approximately 18 nominal engineering days, with high overall uncertainty. This is not a delivery commitment.

Use fake OAuth/MCP services and isolated state for tests. Real phone/client acceptance needs scratch instances and explicit permission. No live setup or implementation has started.
