LEG-199 · proposal revision 3 · awaiting overall approval

App receiver.
Or local web only.

Legato creates PKCE/state, exchanges the code and stores tokens. The receiver runs on the browser's device.

App with local or remote Legato

sequenceDiagram
participant A as Native app
participant B as Device browser
participant S as Legato server
participant P as Provider
A->>A: Prepare callback receiver
A->>S: Authenticated begin with receiver binding
S->>S: Create state and sealed PKCE
S-->>A: Authorization URL and transaction binding
A->>B: Open consent URL
B->>P: Authorize
P-->>B: Redirect to app callback
B->>A: Authorization response
A->>S: Authenticated code and state delivery
S->>P: Exchange code using server verifier
P-->>S: Tokens
S-->>A: Account confirmation status

The app records which paired instance started the transaction. It posts only to that instance, even if the operator switches servers during consent.

Desktop uses an app-owned loopback listener. Phone receiver/browser-handoff behavior needs separate platform and provider verification. Existing pairing links do not implement OAuth capture.

What stays on Legato?

PKCE verifier, client secrets, provider tokens, refresh and agent grants. The app holds the short-lived authorization response only in native memory. It never sends codes through the webview or conversation.

Browser on the Go server's machine

sequenceDiagram
participant W as Local browser
participant S as Go server
participant P as Provider
W->>S: Authenticated Connect
S->>S: Bind temporary loopback listener
S->>S: Create state and PKCE
S-->>W: Authorization URL
W->>P: Authorize
P-->>W: Redirect to localhost receiver
W->>S: Loopback callback
S->>P: Exchange code using server verifier
P-->>S: Tokens
W->>S: Poll status and confirm account

The frontend asks Go to start the receiver and opens consent in its current browser. Go does not launch a browser on the host.

Browser-only connection setup requires Legato on this computer. For a remote server, use the Legato app.

No topology detection: a remote no-app browser will redirect to its own localhost, fail to reach the Go receiver, and time out. Cancel or retry from a supported mode; never paste the failed redirect.

Settled product scope

  • Native app, or browser and Go server on the same machine.
  • No public Legato OAuth callback or callback-origin onboarding.
  • No tunnel, hosted relay, remote-web fallback or smart topology detection.
  • Registration declares the actual receiver callback automatically where supported. Provider loopback/port/scheme restrictions still apply.
  • CIMD still needs provider-readable metadata. No new public metadata service is implied.
  • Account confirmation remains selected. Agent tools remain default-deny, independently of OAuth consent.
Required acceptance

Test app-to-paired-server binding, wrong server, server switching, replay, disconnect, receiver cancellation and expiry. Verify local web through its real begin/listener/callback path. Test remote web failure honestly.

Refresh must work after the app closes. Re-authentication requires an app or local web. Native phone background handling is not verified by the earlier direct HTTPS callback tests.

Current decision: docs/analysis/leg-199-app-local-callbacks.md. Previous scenario evidence is historical. No feature implementation or native-flow testing has occurred.
