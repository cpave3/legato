Changes to the plan

  • Generate redirect declarations through usable CIMD/DCR. Manual client setup is advanced, not the default form.
  • Reuse the pinned instance address, or approve it once in phone Settings. Do not require a host-file edit for first setup.
  • Specify the CIMD publisher, its public reachability and its cache/version behavior.
  • Require generation checks, disconnect cancellation and durable attempts across web processes.
  • Prevent the SDK's legacy endpoint-guessing fallback.
What remains unverified?

Actual provider policies, phone VPN/DNS/TLS, native app return behavior, sealed-store integration and two-agent tool grants. The fixtures use synthetic memory secrets and local TLS. No real accounts, running-instance tests or feature code changed.

A phone route to the callback is separate from provider access to CIMD. Public metadata does not automatically mean a provider permits the callback; DCR does not override redirect policy.
