# Even Hub glasses app

`packages/even-hub/` is a proof of concept (LEG-163): an Even Realities G2 glasses app that lets the operator pick one of the Legatos saved in the Legato Android app, shows the agents running now on two tabs (Active, the Reeve first and then needs-you first; Idle), opens a chat with the instance's Reeve, lists the approvals waiting and allows or denies those that need no signature, opens an agent to show its recent conversation, sends either a message the operator dictates, and folds into one row across the top (background mode). It is a TypeScript web app on the Even Hub SDK, and the first app in the `packages/` workspace. Since LEG-474 it is a companion to the Legato Android app (`mobile/`) on the same phone: it reads Legato only through that app's glasses link at `http://127.0.0.1:8792`, paired once with a code, and holds no Legato address or token (see § The phone link). The user-facing page is [`site/src/content/docs/integrations/even-g2.md`](../../site/src/content/docs/integrations/even-g2.md); the package's README says how to run it.

## The `packages/` workspace

- One pnpm workspace rooted at `packages/` (`packages/pnpm-workspace.yaml`, `packages: ["*"]`), with one lockfile (`packages/pnpm-lock.yaml`). It is not at the repository root on purpose: pnpm finds the nearest `pnpm-workspace.yaml` above the current folder, so a root one would take over `pnpm install` in `web/`, `site/` and `browser-extension/`, installing at the root and ignoring their own lockfiles. Checked with pnpm 11.21. `desktop/` has its own `pnpm-workspace.yaml` (for `allowBuilds`), so it would be its own root either way.
- Shared by every package: `packages/eslint.config.js` (ESLint finds it from a package folder too; a package's `src/` gets browser globals, everything else Node's), `packages/tsconfig.base.json` (each package's `tsconfig.json` extends it), and `packages/package.json` (the lint dependencies; `pnpm run check` = lint, then each package's `typecheck` and `test`). `even-hub` type-checks `src/` with browser types only (`tsconfig.json`) and `dev/` and the Vite config with Node's (`tsconfig.node.json`), so Node in the app fails `typecheck`.
- Node 22.13 or later: pnpm 11 needs it (`engines` in each `package.json`).
- A package gives itself the scripts `typecheck` and `test`, and the `check` script runs them across the workspace.
- Wired in: `task packages:install` / `task packages:check`; CI job `packages` in `.github/workflows/ci.yml`; `.gitignore` entries for `node_modules`, `dist`, `.pack` and `.env.local` under `packages/`.

## The Even Hub platform, as the POC found it

From the docs at <https://hub.evenrealities.com/docs> and the npm packages, November 2026: SDK `@evenrealities/even_hub_sdk` 0.0.16, simulator `@evenrealities/evenhub-simulator` 0.9.5, packer `@evenrealities/evenhub-cli` 0.2.0, font metrics `@evenrealities/pretext` 0.1.4. None needs an Even account, except `evenhub login`/`create`/`upload`.

- **Where code runs.** In a WebView inside the Even Realities phone app (Chromium on Android, WKWebView on iOS). The glasses run no app code: the phone app sends them container layouts over Bluetooth and sends input back. `await waitForEvenAppBridge()` first; other calls before it silently do nothing.
- **Display.** 576×288 px, 4-bit greyscale shown as green, no fill. At most 4 image and 8 other containers on a page, exactly one with `isEventCapture: 1`. One firmware font, not monospaced, 27 px lines, no size or alignment. Text: 1000 characters on create or rebuild, 2000 on `textContainerUpgrade`; a captured container that overflows scrolls in firmware. List containers: 20 items of up to 64 characters, and no update in place. `textColor` 0–4 is per container.
- **Page calls.** `createStartUpPageContainer` once; `textContainerUpgrade` to change text without flicker; `rebuildPageContainer` for a new layout (flickers); `shutDownPageContainer(1)` from the root page (the system's exit dialog; review rejects a silent exit).
- **Input.** Up, down, click, double click, long press, contextual menu, from the temples or the R1 ring. The simulator reports a click on a captured text container as `{"sysEvent":{"eventSource":1}}` (no type: `CLICK_EVENT` is 0, which the SDK leaves out) and a double click as `sysEvent` type 3, not as `textEvent`s; scrolling comes as `textEvent` type 1 or 2. `startGlance` takes clicks and double clicks from either.
- **Network.** `fetch` and WebSockets from the WebView. A packed app may reach only the origins in `app.json`'s `network` whitelist (full origins, no wildcards), and normal CORS applies, with Private Network Access for loopback: the glasses link answers `Access-Control-Allow-Private-Network: true` on a preflight. On Android the WebView may be suspended in the background, losing memory and open sockets.
- **Secrets.** The docs say never to put keys in an `.ehpk`: anyone can unpack one.
- **Simulator.** A Tauri window (WebKitGTK on Linux). `--automation-port N` serves `/api/ping`, `/api/screenshot/glasses` (RGBA PNG; lit is alpha > 0), `/api/screenshot/webview`, `/api/console` and `POST /api/input`. It does not draw the exit dialog: after `shutDownPageContainer(1)` the display goes blank and its log says `ShutDownPageContainer`. Under Legato's sandbox, the session's X display refuses it; `xvfb-run -a` works (`task even-hub:screenshots -- --headless`).

## The phone link

The protocol is the milestone LEG-474's, and the Android side is in [`mobile/README.md`](../../mobile/README.md) § The glasses link. In short:

- The Legato app's Glasses screen has a switch; switched on, it makes a pairing code (24 base32 characters) and listens on `127.0.0.1:8792` in a foreground service. The operator copies the code into the glasses app's page in the Even app (`legato.phone.code` in the bridge's storage). "New code" in the Legato app revokes the old one at once.
- Every request but a preflight carries `Authorization: Bearer <code>`. The routes: `GET /v1/instances` (`[{id, name}]`, the Legato app's saved servers in its order), and under `/v1/instances/{id}` the seven Legato calls, each passed on with that instance's own token and pinned certificate. The Legato app rebuilds each POST's body from the one field the call needs. Anything else is `404`.
- The Legato app's own answers: `401` (the code is wrong or missing; Legato's own `401` reaches the glasses as a `502`, so a `401` is always the code), `404 {"error":"unknown instance"}`, `502 {"error"}` (Legato couldn't be reached, timed out, or refused the app's token). Legato's other answers pass back as they came.
- The port is fixed because the packed whitelist is fixed when packed (`app.json`: `["http://127.0.0.1:8792"]`). Psi's glasses link uses 8791, so both can run.

## How the app works

- `src/picker.ts`: `picker(instances, {problem, read, updatedAt})` → the picker page: `title` ("Legato"), `status`, `clock`, and `items`, one per instance (`fitItem(name)`, `open: <id>`), at most 20 (`+N more`). Before the first answer "Reading the Legato app…"; a read that failed with no list, "No Legatos to show."; an empty list, "Add a Legato in the Legato app."
- `src/glance.ts`: `glance(agents, {tab, updatedAt, now, problem, approvals})` (`clock` is `HH:MM` of the last read, after its age once that is a minute or more: `3m · HH:MM`, `1h+ · HH:MM`; `startGlance` looks again every 30 s, `AGE_TICK_MS`, and sends it only when it changes; a hold into or out of background mode reads at once) → the list page: `tab`, the tab labels (`Active N`, `Idle N`), `status` (a problem, or ""), `clock` and `items`. Running agents only (`status == "running"`). The active tab holds every agent not idle, ordered `waiting`, `error`, `working`, `background` (the TUI's sections and words, `internal/tui/agents/list.go`), each group oldest first, then the item `Idle agents (N) →` (`go: "idle"`); the idle tab holds the idle ones, then `← Active agents (N)`. An item that opens an agent has `open: <task_id>`. Items are cut by `fitItem` to the list's width (`pxTruncate`'s measure) and to 63 UTF-8 bytes, with `…`; more than 20 end in `+N more`.
- Reeve item (`reeveItem`, in `glance.ts`): the active tab's first item, always, `◆ Reeve  <word>` with `reeve: true`: `ready` (idle), `working`, the TUI's word otherwise, `asleep` when no running agent is marked `reeve` (`/api/agents` marks the current session's). The Reeve's agent is on neither tab nor count, so the active tab keeps 19 items for the rest.
- `src/reeve.ts`: `reeveChat(reeve, read, {instance, pending})` → the chat page `{badge, title, asked, reply, hint}`: the badge `○ ready`, `▶ working`, `○ asleep` (no running agent) or the agents' mark and word; the title `Reeve · <instance>`; `asked`, the last user turn (`speaker`: `You` for `[legato glasses]` and `[legato voice]`, whose resume snapshot after `\n\n[legato]` is cut; `Legato <kind>` for Legato's own) cut to the frame's width (`CHAT_WIDTH`); `reply`, the assistant texts after it joined by blank lines and stripped of Markdown (`plain`: headings, `**`, backticks, links, list marks as `•`), preceded by what the Reeve asks (`Asks: …` with numbered options, or its permission); with no text yet while it works, `Thinking…` and its newest tool call (`▶ legato_api: …`); with no user turn, "Hold to talk to the Reeve."; while `pending` (a message just sent) is not yet the last user turn (`heard`), `You: <pending>` and `Thinking…`. `reeveDictation(instance, step)` is `agent.ts`'s `dictation` with "Speak to the Reeve." and "Sent to the Reeve.".
- `src/approvals.ts`: `approvalsPage(approvals, instance)` (a feed page: `● to approve`, `N waiting · <instance>`, a line each `<mark> <who> <title>` with the ID as `detail`; `●` `actionable` (options, not `signed`), `◇` signed, `○` neither; `who` is "Reeve" for a `reeve*` source, else the task); `approvalPage(a)` (`● approve?` with the title cut to `APPROVAL_BODY_LINES` (2) lines by `measureTextWrap` and the option labels, or, for one the glasses cannot decide, the whole request with "approve it on your phone" or "answer it on your phone or in Legato" and no options); `decisionPage(a, decision)` (`Allow?`/`Deny?` with the option and the whole request: title, summary, `details.reason`; `Deciding`, `Allowed`/`Denied`, `▲ Not decided` with a tap to try again). Every badge fits the badge box (tested).
- `src/background.ts`: `background(agents, {problem, battery, charging})` → `{alert, counts}`: `alert`, left-aligned and bright, `● N` waiting and `▲ N` error (the Reeve counted too), `▲ can't read` while a read fails, and `▲ G2 N%` at `LOW_BATTERY` (20) or less, not charging; `counts`, right-aligned by leading spaces in `COUNTS_TEXT_WIDTH` and dim, `▶ N`, `▷ N`, `○ N` (not the Reeve) and `G2 N%`, joined by `  ·  `; `no agents` when both would be empty. Groups with none are left out.
- `src/layout.ts`: one spacing scale for every page (8 px margin, 4 px gap and padding, 1 px borders), the header row, the frame under it and the hint line at the foot, and `center` (leading spaces; the firmware only aligns left). A box is `boxHeight(padding, border)` tall: a 27 px line inside its padding and border, else the simulator (and likely the firmware) gives it a scrollbar.
- `src/agent.ts`: an agent's pages share a header: `badge` (its state, `● needs you`, in a bordered box, bright) and `title` (task and title, dim). `agentPage(agent, read)` → `{badge, title, items, hint}`: the feed, a list of one-line entries (`● Asks: …` for the open permission or question, then the entries newest first: `You: …`, `Agent: …` for what it said, `Legato <kind>: …` or `Agent <id>: …` for a tagged user turn read as `web/src/lib/legatoMessage.ts` reads it, a tool call as `<mark> <tool>: <what>` with `▶` running, `▲` failed, `·` done and an MCP tool by the part after its last `__`), each cut by `fitItem` and each keeping the entry in full as `detail`; at most 20. `entryPage(agent, item)` shows one entry's `detail` in the frame (within 2000 characters). `dictationPage(agent, step)` draws the steps of a message with the step in the badge (`● Listening`, `Message`, `Sending`, `Sent`, `▲ Not sent`, `▲ Problem`). Every page's `hint` is centred: `Tap: expand · Hold: dictate · Double tap: back` on the feed. A problem from sending keeps the text, and a tap sends it again.
- `src/legato.ts`: the calls, through the phone link (`Phone`: `url`, `code`; `PHONE_URL`). `fetchInstances` (`GET /v1/instances`, checked to be `[{id, name}]`); then, each with the instance's ID, `fetchAgents`; `fetchConversation` (409 → "it is starting, or it runs in a terminal": Legato answers 409 both for an agent driven through its terminal and for a native one whose bridge is not up yet; 404 → "no longer running"); `transcribe` (`POST …/api/voice/transcribe` `{transcription_only: true, pcm: <base64>}`: never `false`, which would have Legato type the text into the agent's pane itself; 404 → "Transcription is off", a 200 with `error`, empty text → "Heard nothing."); `sendMessage` (`POST …/api/agents/{task}/chimera/send` `{content}`, which reaches only an agent with a native endpoint and never starts one; 409 busy, 503 no native endpoint); `messageReeve` (`POST …/api/reeve/message` `{text, from: "glasses"}`, which starts or resumes the Reeve when none runs; 503 → "This Legato has no Reeve."); `fetchApprovals` (`GET …/api/approvals?status=pending`, checked to hold a list); `decideApproval` (`POST …/api/approvals/{id}/decision` `{decision, option?}`; 409 → "It was already decided somewhere else.", Legato's own words otherwise, such as a signature it needs). `fetchConversation` takes a `limit` (`REEVE_ENTRIES`, 50, for the Reeve's chat, so it reaches back past a turn's tool calls to the message that started it). `POST /api/tasks/{id}/agent` was not used for sending because it starts an agent when none runs. `chimera/send` does not queue: the web UI sends over `/ws` (`agent_message` with `queue: busy`, to `AgentService.QueueMessage`), so a message to a working agent waits there, while the glasses get 409 and keep the text to send again. An HTTP route to `QueueMessage` would let the glasses queue too (see Ideas). The phone's own answers, read first in `call`: no code saved (`code: ""`) → "Not paired with the Legato app" and nothing is sent; a network failure → "Can't reach the Legato app on this phone"; `401` → "The Legato app refused the pairing code"; `404` with `error: "unknown instance"` → "That Legato is no longer in the app" with `gone: true`; `404` with `error: "not served to the glasses"` (a Legato app older than the call) → "Update the Legato app on this phone: it can't pass this on yet."; `502` → the phone's `error`, else "Can't reach Legato". Any other failed answer is Legato's `{"error"}` when it gave one. Every call gives up after `CALL_TIMEOUT_MS` (15 s; transcription `TRANSCRIBE_TIMEOUT_MS`, 35 s), a little longer than the phone gives Legato (10 s, 30 s), so the phone's own `502` arrives first: "The Legato app took too long to answer". `code: false` sends no `Authorization` header, for the dev server's fake phone. The dictated text is the operator's own words, so it carries no `[legato …]` tag (see [Development notes](dev-notes.md)).
- `src/app.ts`: `startGlance(bridge, legato)` (a `LegatoClient`: `instances()`, then `agents`, `conversation`, `transcribe` and `send`, each given the instance's ID). The first page is the picker (`legatos`, a framed list where the list page's is, with a bordered `title` where its tabs are, `status` and `clock`). On the first list read with exactly one instance, it opens that one without showing the picker, and a double tap on its active tab exits; an instance tapped in the picker (matched by index when the item there has the name pressed, since two Legatos may share a name, else by name) opens with a fresh list, polling reads it, and a double tap on its active tab goes back to the picker, which reads the list again. A double tap on the picker exits (`shutDownPageContainer(1)`). While the picker is in front, polling reads the list of instances. When `agents` or `conversation` answers `gone` (the phone's `404 unknown instance`), the app goes back to the picker with that problem in its header (`leftBecause`, kept until another instance is opened; a failed list read shows its own problem first) and reads the list again. Every change of state runs through one promise queue (reads, presses, the recording clock), so nothing races; sound (`audioEvent.audioPcm`) is kept outside it as it arrives. A press is judged against what the glasses showed when it came (`seen()`: the view, the dictation step, the list's items), not when its turn comes: a tap made while "Transcribing…" showed is dropped, so it cannot send the transcript that replaced it, and a list press is matched by the item's name among the items then shown (by index only when the SDK gives no name). The next poll is set in a `finally`, so a failed call to the glasses or to Legato does not stop polling. Out of the foreground (`FOREGROUND_EXIT`, which the glasses send when their screen goes off) the app polls every `BACKGROUND_POLL_MS` (30 s, or what the phone page's setting gives, or not at all) instead of stopping, and `FOREGROUND_ENTER` reads at once. Since waking the screen sends nothing, any other event from the glasses while out of the foreground (a press, a scroll) is taken for the operator looking again: the app is back in front, reads at once when its last read (`readAt`) is `POLL_MS` old or more, and polls every `POLL_MS` from then on. Before this (found by scenario tests, 2026-11-23) one screen-off left the app polling at the screen-off rate, or not at all, until the G2 menu was opened. Each poll reads the agents, the approvals and the open conversation at once (`Promise.all` in `readInstance`), so a slow call holds back none of the others; the Reeve's chat reads the Reeve the last list had, and again should the new list name another. An agent's view and the Reeve's keep their conversation as a `Reading` (`took`): the last answer, `readAt` of the last that worked, and `problem` when a later one failed, which keeps that one up; the page models take it as `Freshness` and put the problem in the title in place of the agent's (`RUN-1 ▲ Can't reach Legato`) and how old it is at the end of the title once a minute or more (`freshTitle`: `· 3m`, kept whole when the title is cut). `AGE_TICK_MS` redraws whatever page is in front, sending only text that changed. A double tap back from an entry draws the feed at once, then reads it again. The feed draws the conversation's extra fields (see [Web UI](web-ui.md) § the conversation endpoint), newest first: `live.thinking` as `Thinking: …` and `live.reply` as `Writing: …` above the entries (under `● Asks`), a running subagent's newest call as `└ <tool>: <what>` above the call that started it (marked `▶` while the subagent runs), and an entry's `thinking` as `Thought: …` under it. The Reeve's chat adds `live.reply` to its reply, ending in `…`. Transcription runs outside the queue, its answer coming back through it only to the same dictation (`asked`), so a double tap on Transcribing… drops the message at once and polling goes on meanwhile. An approval Legato no longer lists is left from its options, a choice not yet confirmed, or a failed decision (Not decided), but not while the glasses' own decision is under way or just done. Seen on the operator's G2, 2026-11-23: the screen going off sends `FOREGROUND_EXIT` (once preceded by an enter), waking it sends nothing, and opening the G2 menu sends `FOREGROUND_ENTER`; the SDK has no other event for the display. An app that stopped reading on the exit showed what it had drawn last until something else woke it. `draw` redraws a page (`createStartUpPageContainer` once, then `rebuildPageContainer`; when the glasses refuse the first page, as they do after the app's page reloads in the same session (a dev server's reload, seen on hardware 2026-11-23: the app hung on the old page with no input handled), it is rebuilt instead; a `false` from it is an error and the page stays undrawn, so the next refresh draws it again) only when its layout key changes: the list's key is the tab and items, a feed's its task and items (a list cannot change in place, so a new entry redraws it and the highlight goes back to the top), a text page's its task. Otherwise only text that changed goes out with `textContainerUpgrade`; text that became empty goes out as one space, since the G2 glasses ignore an update to empty text and keep the old one (seen on hardware, 2026-11-23: background mode's bright side stayed after the agent was answered). A page is drawn with text over 1000 characters left empty, then updated (the limits differ). Presses come from `listEvent`, `textEvent` or `sysEvent` (`press`); a list press is matched to an item by `currentSelectItemName`, then `currentSelectItemIndex`. Pages: the list page (tabs, problem, clock, a framed list), an agent's feed (badge, title, framed list `feed`, hint) and its text page (the same with a framed text `body`, for an entry or a message; switching between them updates in place). Hold to talk: `LONG_PRESS_EVENT` on a feed, an entry or a problem starts recording, and `LONG_PRESS_RELEASE_EVENT` stops it (a release is not judged against what was shown: the hold ahead of it in the queue started the recording); a tap stops it too, should a release not come. A tap on a feed line opens it (by name, as with the list); double tap goes back one step. Dictation: `audioControl(true, AudioInputSource.Glasses)` (`false` from it → "The microphone didn't start."), a one-second clock, a stop at 60 s, `audioControl(false)` on stop, cancel and backgrounding.
- Approvals in `startGlance` (`LegatoClient.approvals`, `decide`; views `approvals` and `approval`): each read of the instance also reads the approvals (the last list stays when that fails), and the list page gets `● To approve (N) →` under the Reeve (`glance`'s `approvals`). An approval opened from the list, or from an agent's `● Asks:` line (`FeedItem.asks`; the first pending approval of that task from an `agent_*` source), goes back where it came from. Its layout: badge, title, the brief title (two lines, bright), and the options as a framed list at `OPTIONS_Y`, captured. A tap on an option makes `decision` `confirm`; the next tap, judged against the step seen when it came (`seen().step`, so a tap queued behind the choice is not a confirmation), sends it; `done` shows for `SENT_MS`, then the approval leaves the list, the view goes back and the instance is read again. A failed decision keeps the option and a tap tries again. An approval no longer pending when read sends the view back, unless the glasses' own decision is under way or just done.
- The Reeve and background mode in `startGlance` (views `reeve` and `background`; `LegatoClient.reeve`): a tap on the Reeve item opens its chat (layout: badge, title, `asked` dim at the top of the frame's place, `reply` framed under it and captured, hint), reading the Reeve's agent's conversation (`limit` 50) when one runs, now and on each poll. Hold, release, review and tap send as for an agent, but through `reeve`; after "Sent" the chat shows the message as `pending` until its conversation has it, and the list is read at once (a Reeve the message woke is running now). A tap on the chat opens the Reeve's agent's feed (`AgentView.back`), whose double tap comes back to the chat; a double tap on the chat goes to the list. A hold on the list switches to background mode (layout: `alert` and `counts` side by side across the top, `counts` captured), drawn from the same poll; there only a hold goes back, so a brushed temple does nothing. The glasses' battery: `getDeviceInfo()` after the first read (at most `DEVICE_TIMEOUT_MS`, 2 s, since every press waits behind it in the queue), kept only for a glasses model (`DeviceModel.isGlasses`), then `onDeviceStatusChanged` for that serial number only (the ring's status is someone else's). The list page and the picker now have the hint line at the foot too (the frame is `FRAME_HEIGHT_WITH_HINT`): `Tap: open · Hold: background · Double tap: back|exit` and `Tap: open · Double tap: exit`. Sound is kept up to a minute's worth (`MAX_RECORDING_BYTES`, 1.92 MB), however fast it comes: the simulator's null microphone sends it as fast as it can, which made recordings past the Legato app's 8 MB limit.
- `src/settings.ts` also keeps how often to read while the glasses' screen is off (`legato.screen-off`: `30`, `60` or `off`, 30 when unset or unknown; `loadScreenOff`, `saveScreenOff`, `screenOffMs`), chosen on the phone page and passed to `startGlance` as `screenOffReadMs`, asked each time a read is set, so a change applies from the next one (a read already set still comes); off sets none until the app is back in front or a hold switches background mode.
- `src/settings.ts`: the pairing code, in the bridge's `getLocalStorage`/`setLocalStorage` (`legato.phone.code`). `saveCode` strips spaces and dashes, upper-cases, and accepts base32 (`A–Z`, `2–7`) of 16 to 64 characters; an empty code forgets the saved one.
- `src/main.ts`, `index.html`: the phone-side page (the code field, and whether it is paired), and the client `startGlance` is given. The app reads `PHONE_URL`, except in the dev server, where it reads the fake phone at `/phone` (`code: false`) unless the dev server was started with `VITE_LEGATO_PHONE=real`, to sideload it onto the glasses.
- `src/dev-log.ts`: dev builds only. The Even app's WebView on Android has no DevTools, so `relayConsole` copies `console.log`/`info`/`warn`/`error` to the dev server's `POST /__log`, and `loggedFetch` logs each call to the phone (method, address, status and time, never the code). `main.ts` imports it behind `import.meta.env.DEV`, which a build replaces with `false`, so the build leaves it out; `scripts/pack.mjs` fails if `/__log` is in the built JS.
- `dev/legato-dev.ts`: the Vite dev server as a fake phone at `/phone`, answering the phone link's protocol from the fixtures (`answerPhone`): two instances, `Desk` (`fixtures/agents.json`, or `LEGATO_FIXTURE`) and `Laptop` (`fixtures/empty.json`), `fixtures/conversation.json` as any agent's, `fixtures/reeve.json` as the conversation of an agent its list marks `reeve`, `fixtures/approvals.json` as Desk's pending approvals (one of each mark) and a decision only logged, a set transcript, and a send, to an agent or the Reeve, that is only logged. It asks for no code. The routes, `404`s, `415` for a POST that is not JSON, `400` for a body without its field, `404 unknown instance`, the preflight's headers and every answer's `Access-Control-Allow-Origin: *`, `Cache-Control: no-store`, `Connection: close` are the Legato app's. A body over 8 MB is answered `413`. It also prints what `POST /__log` is sent (`logLine`, 64 KiB at most). Nothing in it reaches a real Legato.
- `scripts/beta.mjs` (`pnpm run beta`, `task even-hub:beta`): `evenhub self-check` (exit 2: tells the operator to run `evenhub login`, which only they can), then the version (`--version`, else `app.json`'s patch + 1, else as it is with `--create`) written to `app.json`, `scripts/pack.mjs`, `evenhub upload dist/legato.ehpk -m <changelog>` (or `evenhub create` with the name and tagline for `--create`), and `evenhub promote <version> --to beta`, each with `--json` (its `message` and `hint` printed on failure). A failed pack or upload puts `app.json` back; exit 3 says to use `--create`, exit 4 that the version exists. The changelog is `-m`, else the subject of the latest commit to the package. `scripts/beta-plan.mjs` holds the parts that decide (`parseArgs`, `nextVersion`), tested by `beta-plan.test.mjs`. The operator's account had `dev.legato.glance` 0.1.0 on beta on 2026-11-23.
- `scripts/pack.mjs`: `vite build`, the check that the dev log relay is not in it, then `evenhub pack app.json dist -o dist/legato.ehpk --sdk-ver <installed SDK>`. `app.json` asks for `network` (whitelist `["http://127.0.0.1:8792"]`) and `g2-microphone`. ## Ideas for later

- An HTTP route to `AgentService.QueueMessage` (as `/ws`'s `agent_message` with `queue: busy`), so a message dictated to a working agent waits for it instead of being refused.
- A token scoped to what the glasses do (read agents and conversations, transcribe, send), instead of each instance's whole web token, which the Legato app holds.
- Run dictation end to end against a scratch Legato with `voice.whisper_url` set and a native agent running, and on real glasses (the audio format is assumed to be the 16 kHz mono s16le the simulator documents).
- Answer a question from the glasses: its options as a list, as an approval's are (permissions and other approvals without a signature are decided there already).
- Count the approvals waiting in background mode's bright side.
- Use `internal/engine/endofturn` (or Legato's voice session, `/api/reeve/voice/session`) to stop recording when the operator stops speaking, instead of a second tap.
- Keep the list's highlight on the same agent across a redraw: the SDK has no call to set it, so the app would have to redraw less, or keep its own cursor in a text container.
- Show the title alone for ad-hoc agents, whose task IDs (`ixkm5deo`) say nothing.
- Hold a stream open while in front and read on `agents_changed`, with polling as the fallback (the phone link would have to pass on `/ws`, or long-poll as Psi's link does).
- Notify on a change to `waiting`: the SDK has no notification call. The app would have to be in front, or Legato's ntfy notifications would have to reach the phone.
