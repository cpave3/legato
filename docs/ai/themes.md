# Client themes

## Source and scope

[`DESIGN.md`](../../DESIGN.md) records the approved visual intent and component guidance (The Control Room). Its frontmatter binds existing roles; it does not supersede the canonical palette/derivation contract below. `.impeccable/design.json` supplies documentation previews, not runtime components.

`themes/palettes.json` is the canonical semantic/syntax source for `dracula`, `ocular-light`, `ocular-dark`; `legato` preserves each client's existing default. `themes/README.md` records the research source hash/date, naming, rendering contract and Dracula attribution/license. Runtime never reads the research resource. Ocular is not a proven fatigue intervention.

Web and desktop import the source through `themes/render.ts`; Android packages the same JSON as a build asset. Canonical research values remain unchanged. A terminal-safe view falls back to foreground for faint secondary/comment text and to focus for an insufficient control boundary. Separately, `materials` derives recessed rail, panel, raised, divider and status-wash roles from shared sRGB recipes; the reading canvas stays exact. `material_ink_contract` blends original UI ink toward foreground in 5% steps until it passes 4.5:1 across canvas, selection and all material surfaces (except divider). This preserves a readable secondary hierarchy in Dracula instead of flattening metadata to white. Web/desktop use offset contact/ambient shadow tokens, native Android uses Material3 surface levels/elevation. Decorative separators are distinct from required 3:1 control borders. The sandbox/download theme variables and Mermaid fills/ink consume these same material roles, including shared shadow tokens. No page owns an alternate palette; Legato defaults, terminal ANSI, IDs and saved choices are unchanged.

`web/src/lib/appTheme.ts` owns browser identity/state/change: `appTheme()`, `setAppTheme(id)`, `applyAppTheme()`, `subscribeTheme()`. `legato:app-theme` persists the app ID. Missing/unknown IDs fall back to `legato` without rewriting unrelated preferences. The public DOM signal is `legato:theme-changed`. Application starts apply the preference before React mounts; local changes apply immediately, and storage events synchronize other tabs. A rejected storage/native save reaches the picker as an alert.

App theme is a **device/client preference**, not a server setting or an MQTT field. No new config registry setting, database migration, server route, broker subscription or command authority is introduced. The existing `theme` config entry is separate and is not used as the browser's new app-theme preference. No system-appearance mode existed; none is invented here. `web.tint` remains a server identity colour and is neither a theme nor overwritten when themes change.

## Surfaces

- **Web/PWA:** Settings › Appearance › App theme. `main.tsx` applies semantic CSS variables; `theme.css` covers selection, caret, focus, controls and scrollbars. Existing Tailwind neutral scales are mapped by role. `scripts/theme-utilities.mjs` maps legacy chromatic ink/washes/boundaries to the same roles; regenerate and run `--check` after changing utility use. Hardcoded application colours use semantic variables with original-value fallbacks so Legato's palette is preserved. User/server tint colours, media, QR codes and externally authored pages are not globally recoloured.
- **Terminals:** Settings › Terminal theme retains Legato, Night, Solarized Dark and Classic, adds the three themes and Follow app. `legato:terminal-theme` is unchanged. Existing saved overrides are preserved; missing/unknown/`app` follows the app. Both `LiveTerminal` and `TerminalPanel` update xterm's `options.theme` in place, not by rebuilding the terminal, reconnecting, resetting scrollback or resending input. ANSI normal/bright, cursor and active/inactive selection come from the canonical roles. Ocular keeps ANSI ink unchanged when selected; Dracula uses foreground selection ink because some original hues fail contrast on its selection colour. Explicit truecolour/RGB, OSC palette overrides and backgrounds emitted by remote applications can override xterm's palette; Legato does not rewrite terminal bytes or reconfigure those tools.
- **Native conversation, diffs, cards and artifacts:** role-based foreground/surface colours, unchanged added/removed markers, selected ranges and labelled statuses. Sandboxed HTML has an isolated theme document, rebuilt when the app theme changes; downloads capture the selected theme. Mermaid and Wiremark use the same polarity/roles and redraw on change. An author's explicit colours can still override supplied artifact variables; a separately authored review briefing owns its own theme.
- **Desktop:** native persisted `app_theme`, shell picker, key-bound page requests, save-before-delivery, all retained/new server views and reload paths. See [Desktop](desktop.md). Remote pages gain no Tauri command capability. System-native dialogs, certificate trust prompts and OS controls remain platform-owned.
- **Android:** native persisted choice, Compose role mappings and system bars, native picker and WebView delivery. See `mobile/README.md`. The WebView's origin-restricted bridge and top-frame key remain required. The on-screen keyboard, camera and system fingerprint/file-picker dialogs remain OS-owned.
- **Terminal TUI / other tools:** no change to the standalone Bubble Tea palette, external editors, tmux applications or the Even G2 display. These are not native desktop/mobile wrapper surfaces.

## Native page contract

A capable app advertises `window.legatoShell.theme = 1`. The web picker posts `{legatoShell:"theme", type:"theme", key, id}` to `ReactNativeWebView.postMessage`, where `id` is one of the four app IDs. It waits for `legato:shell-theme` with `{id, error?}`; refusal/timeout is shown rather than silently saving a page-only preference. The native owner saves first, updates its own shell, writes `legato:app-theme` in retained top-frame server pages and dispatches `legato:theme-changed`; it seeds newly loaded pages with its latest saved choice. A success reply follows delivery. Requests must pass the existing origin/top-frame/key checks and strict ID validation. Terminal preferences remain independent in each server page.

## Future MQTT / Home Assistant contract — not implemented

LEG-157's first MQTT release remains **read-only, ten aggregates**. This branch adds no MQTT theme command/select entity, publishes no theme state there, changes no discovery payload/broker/ACL and depends on none of its runtime files.

A follow-on must define an **instance default** distinct from the current device preference. Recommended contract (proposal, not an available endpoint):

1. Stable values are the four app IDs above; display labels may change. An instance-scoped `ThemePreference` service exposes `Current() -> {id, revision}` and `Change(expected_revision, id, actor)`; it validates IDs, persists before publishing a typed changed event, and reports save/conflict errors. Browser/native adapters continue through the same state/change boundary, rather than editing CSS or localStorage from an MQTT handler.
2. Home Assistant `select` controls that instance default. State is retained `{id, revision}`; command is **non-retained** `{id, expected_revision, command_id}`. Reject retained commands, malformed/unknown IDs, stale revisions, expired/duplicate command IDs and unavailable persistence. Discovery/state never imply permission to command. Publish authoritative state only after a successful save; reconnect republishes state, never replays a command.
3. Clients need an explicit **Follow instance** opt-in before the server can affect them. Existing device choices and saved terminal overrides must not be overwritten. Offline clients converge from an authenticated snapshot plus change revision on reconnect. No such preference/setting is added by this release.
4. Before implementation, decide the authenticated actor and least-privilege `theme.change` grant for one instance, revocation/audit/retention policy, topic ownership, command size/rate limits, availability and error handling. Broker ACLs and HA discovery alone are insufficient authorization. Theme changes are cosmetic, not a channel for executing commands, arbitrary settings or remote paths. Privacy/device targeting and race policy need review with the operator and LEG-157's author.

There is no claim that automatic switching improves fatigue. Do not implement or enable this proposal by extending the read-only MQTT profile implicitly.

## Verification

The regression entry points are the Settings page picker, mounted terminal picker, native shell picker/storage/delivery, artifact builders and actual rendered components. `scripts/verify-themes.mjs` drives an isolated Chromium against an explicitly supplied scratch instance, takes desktop/390px/320px captures, checks picker/reload behaviour and can verify real component contrast via `web/src/test/theme-preview.html`. The fixture imports production components; it creates no review tour, agent or command authority. See the final verification record in `themes/VERIFICATION.md` for exact results and native execution limits. Research prototype tests are not counted as application tests.
