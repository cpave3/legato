## Web UI

Remote web interface for monitoring and interacting with agent sessions from any device (mobile, tablet, second screen). Built with React 19 + Vite + xterm.js + TailwindCSS. Compiled to `internal/server/static/dist/` and embedded in the Go binary via `embed.FS`. Installable as a PWA with offline support.

**Workflows**: `/workflows` lists legacy-global (`~/.legato/workflows`), XDG-global, and project definitions plus run history, generates typed input forms, offers editable repository/path presets from `workflows.repositories` config, and launches runs. Board cards expose a viewport-clamped context menu on right-click and through an accessible action button; it reuses Open/Move/Delete behavior and opens eligible workflows in a separately scrollable, edge-flipping flyout, binding the selected card read-only in the shared run dialog. `/workflows/runs/:runId` shows responsive ordered step progress, executor-specific PR/agent details, attempts, errors, typed outputs, Markdown/file artifacts, retry/cancel controls, and live-agent links. `workflow_changed` WebSocket messages refresh lists/details. Mobile views stack step cards, contain wide JSON/code, use touch-sized controls, and preserve a backlink when opening an agent terminal.

**Learning**: `/learning` lists and filters the local learning ledger and performs FTS claim/rationale search. `/learning/:learningId` shows status/scope/revision, linked evidence provenance, incorporation history, and revision-aware edit/accept/reject controls. Incorporation creation/submission/verification and prompt-manifest browsing currently remain CLI/API surfaces. Learning candidates and verification work also appear through the generic Attention producer. See [Legato Learn](learning.md).

**Task activity**: Board task detail uses `GET /api/tasks/{id}/activity` to show tabs for notes, review tours, plans, and related workflow runs with downloadable managed artifacts. Reviews, plans, and runs link into their existing detail pages. **Open agent** calls `POST /api/tasks/{id}/agent`: live task agents are selected for resume, while absent agents are launched against the existing task with the chosen adapter and working directory. Chimera launches request durable-session resume behavior before navigating to the Agents page.

**Starting**: `legato serve [--port 3080]` for standalone, or `web.enabled: true` in config to auto-start alongside TUI. Auto-start probes the port first — skips if another instance already has it. `Server.Serve(ln)` accepts pre-bound listener to avoid close-rebind race. Server shuts down when TUI exits via `webSrv.Stop()`.

**TLS**: Disabled by default for simple local-network development. Set `web.tls.enabled: true` for auto-generated HTTPS, or set both `web.tls.cert` and `web.tls.key` to enable HTTPS with explicit files. `Server.SetTLS(certFile, keyFile)` configures TLS before `Start()`/`Serve()`. `Serve()` calls `http.Server.ServeTLS` when TLS is set, plain `Serve` otherwise. HTTP/2 is disabled via an empty `TLSNextProto` map because WebSocket upgrades require HTTP/1.1. The web client auto-detects `ws:` versus `wss:`. Auto-generated certificates live at `~/.local/share/legato/certs/`; the server certificate is regenerated when it expires or no longer includes the configured hostname or current local IP addresses, while retaining the CA.

**Authentication**: Bearer token auth on all API/WebSocket requests. Token auto-generated on first server start at `<dataDir>/auth-token` (32 bytes, hex-encoded). `Server.SetAuthToken(token)` configures auth middleware. REST uses `Authorization: Bearer <token>` header, WebSocket uses `?token=` query param. Exempt: `GET /health` (monitoring), `OPTIONS` (CORS preflight), static assets (SPA shell). Web UI checks auth on load — shows `TokenPrompt` modal on 401. Token stored per-server in localStorage (`legato:token:<url>`). Stored token invalidation triggers page reload to re-prompt. `web/src/lib/auth.ts` provides `getToken`/`setToken`/`clearToken`/`authHeaders` helpers.

**CORS**: `Access-Control-Allow-Origin: *` on all responses via `corsMiddleware` in `server.go`. Enables cross-origin access from PWA served by another legato instance. `Access-Control-Allow-Headers` includes `Authorization` for token auth.

**QR pairing**: `legato pair` CLI renders terminal QR code encoding `legato://pair?url=<serverUrl>&token=<token>`. PWA Settings page has "Scan QR Code" button using `html5-qrcode` library — opens device camera, decodes QR, stores server URL + token in one step. Falls back to manual token paste on camera denial. `QRScanner` component in `web/src/components/QRScanner.tsx`.

**PWA**: Installable progressive web app via `vite-plugin-pwa` (Workbox). Service worker auto-updates (`registerType: 'autoUpdate'`), `skipWaiting: true` + `clientsClaim: true` for immediate activation on update. Precaches app shell (HTML/CSS/JS/icons), runtime caches API routes with NetworkFirst strategy. Manifest at `/manifest.webmanifest` (auto-injected by plugin). Icons: `web/public/pwa-192x192.png` and `pwa-512x512.png` (pre-generated from `favicon.svg`). PWA requires HTTPS on non-localhost — hence TLS auto-generation.

**Offline dialog**: `OfflineDialog` (`web/src/components/OfflineDialog.tsx`) is mounted inside the authenticated `Layout` and appears when the WebSocket remains disconnected for two seconds, avoiding a flash on slow initial connections. It keeps the current page rendered behind a centered modal, offers Retry, server switching, Settings/QR actions, and a TLS hint for remote servers. Users can dismiss it with the close control or Escape to inspect cached UI; desktop and mobile navigation retain a red disconnected indicator, and the dialog auto-closes on reconnect and reappears after a later disconnect.

**Cache headers**: `spaHandler` in `internal/server/spa.go` sets `Cache-Control` headers — `public, max-age=31536000, immutable` for Vite hashed `assets/*`, `no-cache` for `sw.js`/`workbox-*.js`/`index.html` and SPA fallback responses.

**Terminal streaming**: `pipe-pane` fans output to all subscribed web clients via WebSocket. Pipe start is deferred until the first `resize` message so the tmux pane is correctly sized before output flows. `PipeOutput` clears any stale pipe-pane from a previous process before starting a new one. On subscribe, the server waits 150ms for SIGWINCH redraw, then sends a `CaptureWithEscapes` snapshot as backfill (`\n` → `\r\n` for xterm.js). After the live pipe starts, the server bounces the pane width by 1 column (shrink then restore) to force a full SIGWINCH redraw through the pipe, preventing the backfill snapshot and live stream from diverging. Output chunks sent synchronously (not `go c.send`) to preserve ordering. Escape sequence buffering (`findIncompleteEscape`) holds back incomplete CSI/OSC sequences at chunk boundaries to prevent xterm.js state corruption. Read buffer is 32KB. `refresh_pane` queries tmux cursor position via `display-message` and appends ANSI CUP to restore cursor after snapshot.

**Native Chimera synchronization**: `NativeAgentPanel` hydrates from the Chimera session snapshot and reduces live envelopes through `web/src/lib/nativeAgentSync.ts`, which owns ordered item insertion, stable assistant/tool identities, bounded event-ID deduplication, and per-assistant streaming buffers. `subscribe_agent` carries the browser's last accepted `cursor`; the server retains a 1,000-event per-agent replay ring and upstream SSE connection for a 30-second disconnect grace period. Known cursors replay missed envelopes before live delivery. Unknown, expired, or cursorless reused streams emit `chimera_sync_required`, causing race-safe snapshot reconciliation. Events arriving during a snapshot fetch are queued and reduced afterward, failed refreshes retain the existing conversation, and completed runs trigger a debounced authoritative repair. Background repair keeps the feed mounted with a lightweight syncing indicator and preserves scroll position. The native panel overflow menu also provides **Refresh from snapshot** for manual recovery. `spawn_agent` calls use a dedicated expanded card that groups each child by Chimera's `parentCallId`, shows its requested agent/model/prompt, and streams forwarded child assistant, reasoning, and tool activity without mixing parallel children. Cursorless browsers loading during an active shared stream receive snapshot repair followed by retained events, so active child cards and captured activity are restored. Live child activity is retained through parent snapshot repair, but not across a full page reload after the shared stream's replay window has expired because Chimera does not persist forwarded `subagent_event` envelopes in the parent snapshot; completed cards then state that no live activity was captured.

**Native composer prefixes**: The native panel mirrors Chimera TUI syntax for idle turns. `@path` grants read access and attaches a bounded file/directory snapshot (line-numbered files up to 2,000 lines / 100 KiB; directories up to 200 entries). `#path` grants write access and attaches the same snapshot. Attachment tokens are parsed and expanded server-side through the Chimera interaction adapter; only idle `SendMessage` triggers expansion, while `QueueMessage` sends plain text. `!command` executes a shell command in the session CWD with a 30-second timeout and 1 MiB output limit via `POST /api/agents/:task_id/chimera/bang`, appends the formatted result to Chimera session context, and resyncs the panel. While busy, `!` commands enter a visible browser-local queue and execute after `run_finished`. Edit tool cards expand by default; other tools remain collapsed. The feed scrolls to the latest message on initial hydration and after explicit send/queue actions.

**Resize protocol**: Web clients send `resize` messages (initial + on container resize + 5s heartbeat for TTL). Server computes min of all web client sizes + attached tmux terminal clients (`tmux list-clients -t <session>`). Only resizes if dimensions actually changed (dedup via `appliedCols`/`appliedRows`). Stale clients expire after 10s TTL. On last client disconnect, resets `window-size` to `latest` so tmux auto-sizes from remaining terminal clients.

**Prompt detection**: `prompt.Detect` runs on captured pane output after 500ms debounce following output. Classifies as `tool_approval` (Yes/Always/No buttons), `plan_approval` (Accept/Reject), or `free_text` (text input). Only shown when agent activity is `"waiting"` (gated on hook state, avoids false positives during active output). Dismissed prompt type tracked in `dismissedPromptTypeRef` — suppresses re-detection of same prompt until user submits text, switches agents, or manually re-detects. Per-agent prompt detection toggle in overflow menu (overrides global default from `legato:prompt-detection` localStorage). Actions rendered as vertical keyboard-navigable list (`ActionList` component): j/k or arrows to navigate, Enter to confirm, Escape to dismiss. On-demand detection via `detect_prompt` WebSocket message (Re-detect prompt in overflow menu).

**Key sending**: `send_keys` WebSocket message. Text ending in `\n` → literal text via `tmux send-keys --` then named `Enter`. No `\n` → space-separated named keys sent in sequence (e.g. `"Down Enter"` → two `SendKey` calls). Used by prompt action buttons, Mode (BTab), Stop (Escape), and free text input.

**Settings API**: `GET /api/settings` returns runtime capability/configuration state: `ca_cert_available`, `working_dir`, `ntfy_configured`, `voice_enabled`, `worktrees_enabled`, and repository presets. `GET /api/ca-cert` serves the auto-generated CA certificate as a PEM download (`Content-Disposition: attachment; filename="legato-ca.pem"`). Returns 404 when using custom TLS config (no auto-generated CA). `Server.SetCACertPath(path)` wired in `main.go` from `resolveTLS` return value.

**Macros API**: `GET /api/macros` returns `{"macros": [{name, keys}, ...]}` from the configured `macros:` YAML list. Auth-protected like other `/api/*` routes. `Server.SetMacros([]macros.Macro)` is called from `cmd/legato/main.go` after `NewWithSwarm`. The `PromptBar` web component fetches via `apiFetch(baseUrl, "/api/macros")` and renders a Macros dropdown next to the action buttons; clicking a macro sends a `send_keys` WS message with the macro's `keys` payload.

**Sparkline data**: `/api/agents` now includes a per-agent `state_timeline` field — a string slice (one entry per bucket, values: `"working"`, `"waiting"`, `""` for idle). Driven by `Store.GetStateTimeline(taskID, window, buckets)`. Window defaults to 10 minutes / 10 buckets and is configured via `Server.SetSparklineWindow(window, buckets)` from the `agents.sparkline_window` config field. `AgentSidebar` renders the timeline as a row of colored divs in each agent card.

**Agent management**: `POST /api/agents/spawn` creates ephemeral agent (title input, defaults to "Ephemeral session"). `POST /api/agents/kill` terminates agent tmux session. Both broadcast `agents_changed`. Dead agent detection: `onStreamEnd` callback fires on pipe-pane EOF → `ReconcileSessions` updates DB → `agents_changed` broadcast → web sidebar filters to `status === "running"` only. Auto-disconnect from selected agent if it dies.

**Mobile support**: Custom touch-to-scroll handler intercepts `touchstart`/`touchmove` on terminal container, calculates swipe delta, calls `term.scrollLines()` directly (xterm.js built-in touch doesn't work on mobile browsers). `touchmove` uses `preventDefault` (non-passive) to block pull-to-refresh. `overscroll-behavior: none` on body as fallback. Floating scroll-to-bottom button appears when scrolled up from bottom (tracks `buffer.active.viewportY < baseY`).

**Collaborative plans**: `/plans` is the queue of proposed and changes-requested plans; `/plans/<plan-id>` renders the immutable Markdown revision with required choices, text-selection comments, revision history data, immediate Q&A, and approve/request-changes/reject actions. `plan_changed` WebSocket messages refresh matching open plans and the queue badge. Comments remain attached to their submitted revision. Required agent-authored questions block approval until answered. See `docs/plans.md`.

**Review tours**: `/review` supports individual and select-all queue selection plus a confirmed **Remove selected** action for stale review packets. `POST /api/review/tours/bulk-delete` validates every selected tour and removes all of their review artifacts in one transaction; a missing tour leaves the entire selection untouched. Removal retains tasks, repositories, worktrees, agent records, and Git history. `/review/<tour-id>` subscribes to `review_changed` WebSocket events and re-fetches the open tour when the event's `tour_id` matches, including answers submitted by agents through `legato review answer`. Diff line-number gutters are selectable: click and drag across rows to select a contiguous range, or click one line and another line in the same hunk to extend it; selecting another hunk replaces the range. Questions send canonical file/hunk/index coordinates, which the server validates against the current step diff and resolves into a durable fenced `diff` block for the agent and Q&A transcript. Transcript messages render safe GitHub-flavored Markdown (plain text remains valid), and delivered questions ask agents to format answers as Markdown. Completed tours stay out of the queue until visible follow-up work exists; when new commits or annotations arrive after a chaptered review, those unreviewed follow-up steps appear alongside the previously reviewed chapters instead of being hidden. The Q&A pane defaults wider and can be resized from its left edge (or with Left/Right on the separator). Its multiline composer sends with Ctrl/Cmd+Enter and, when voice is enabled, can append an editable transcription-only draft without bypassing the review transcript. Each hunk has a local **Viewed** checkbox that collapses/restores its lines, and the step-level reviewed action remains sticky at the top of the scrolling diff pane.

**UI components**:
- `TerminalPanel` — xterm.js terminal with resize reporting, touch scroll, scroll-to-bottom FAB, `[connected]` message on agent switch. Re-sends resize on WebSocket reconnect to restart pipe. `onGlitch` callback triggers glitch animation on terminal sync events
- `NativeAgentPanel` — snapshot-backed Chimera conversation with cursor replay, ordered live reduction, automatic reconnect/run-finish repair, context-window usage, manual **Refresh from snapshot** recovery, edit-diff expansion, skill labeling, message queuing, `@`/`#` path attachments, and `!` bang commands
- `PromptBar` — Primary buttons (Mode, Stop when working) + Macros dropdown (fetches `/api/macros` via `apiFetch(baseUrl, …)` on open; clicking a macro sends `send_keys` with the macro's `keys`) + overflow menu (Refresh terminal, Re-detect prompt, Toggle prompt detection, Disconnect, Kill agent). Tool/plan approval rendered as vertical `ActionList` (j/k navigation, Enter confirm, Escape dismiss). Free text input with arrow key passthrough when empty (Up/Down/Enter/Escape/Tab sent to tmux). Per-agent draft persistence in localStorage (`legato:draft:<agentId>`). Input disabled with "Disconnected..." placeholder when WebSocket is down. Accepts `agentId`, `connected`, `promptDetectionEnabled`, `onTogglePromptDetection`, `onSubmitText` props
- `AgentSidebar` — Agent list with activity badges (working/waiting/idle), working/waiting duration display (Play/Pause icons, muted colors), per-agent **sparkline** rendered from `state_timeline` on the `/api/agents` payload (one colored div per bucket: green=working, yellow=waiting, gray=idle), spawn button (`+`). Desktop sidebar + mobile dropdown. `modifierHeld` prop shows number badges (1-9) for keyboard agent switching
- `WebSocketProvider` — Connection management with exponential backoff reconnect. Appends `?token=` to WebSocket URL for auth
- `OfflineDialog` — Layout-scoped disconnected-state modal with a 2s delay, server recovery actions, accessible dismissal/focus handling, and auto-close on reconnect
- `TokenPrompt` — Modal for entering auth token on first connect or token invalidation. Tests token against `/api/settings`, stores in localStorage on success
- `QRScanner` — Camera-based QR code scanner using `html5-qrcode`. Parses `legato://pair?url=...&token=...` URIs. Error handling for camera denial, invalid QR codes
- `Settings` — Settings page with sections: Appearance (glitch effect toggle, prompt detection default, agent switch modifier key picker), Pairing (QR code scanner), TLS Certificate (CA download with platform instructions). All settings use localStorage with `legato:` prefix

### Board page

The board page (`BoardPage` in `web/src/components/board/BoardPage.tsx`) is a keyboard-driven kanban view backed by `GET /api/board`. It renders columns left-to-right with cards underneath, maintains a selected-card cursor, and supports workspace filtering via a dropdown.

**Keyboard bindings.** `j`/`k` moves the cursor down/up within a column; `h`/`l` switches columns left/right. `n` opens the Create Task overlay (title, description, column, workspace). `x` archives the selected card if it is in the Done column. `Shift+X` opens the Bulk Archive overlay when the Done column has cards (shows count, `y` confirms). `i` opens the Import Remote Task overlay (live search via `SyncService`, j/k navigation, enter to import). `w` opens the workspace switcher (`GET /api/workspaces`, j/k navigation, enter to filter). `?` opens the Help overlay with keybinding reference.

**Mutation feedback and pointer movement.** Board cards support native desktop drag-and-drop between columns in addition to keyboard/click movement. The target column highlights while dragging and the move uses the same task PATCH endpoint as the move dialog. User-triggered mutations show accessible success/error toasts, preserve open form data after failures, and disable repeat submission while pending. Action dialogs render above an open task detail panel. Successful web mutations also broadcast `task_update` over IPC, while embedded TUIs subscribe directly to `EventCardMoved`, so card moves refresh running TUIs in both standalone-server and embedded-server deployments.

**Task worktrees.** When `worktrees.yggdrasil.enabled` is configured, task detail offers **Create worktree**. The modal mirrors the TUI `b` flow with repository presets plus editable primary directory, task-derived branch, and base branch fields. `POST /api/tasks/{id}/worktree` calls the shared `service.WorktreeWorkflow` and Yggdrasil runner; it does not implement a separate web lifecycle. Persisted worktree path/branch metadata is returned by task detail and displayed on later visits. **Open agent** prefers that path as its editable working-directory default, allowing worktree creation and agent launch entirely from the web UI.

**Data flow.** `useBoard()` sets up a WebSocket listener for `cards_changed` messages and automatically re-fetches `/api/board` on every event. The hook also exposes `refresh()` for manual refetch (used after create/import/move/worktree creation). Board data includes PR metadata (check status, review decision, comment count, draft indicator) and swarm stats per card when those services are active.

**Per-card indicators.** Each card shows: priority-colored left border, provider icon (Jira, GitHub, local), warning dot if sync failed, workspace tag in "All" view, branch/PR status pill when a PR is linked, and swarm stat dots (total sub-tasks with done/in-progress counts) when the card has an active swarm. Cards with running agents show a terminal icon.

**Overlay set.** Create overlay (`CreateTaskOverlay`), Import overlay (`ImportOverlay`), workspace switcher (`WorkspaceOverlay`), archive confirmation (`ArchiveOverlay`), link-PR modal (`LinkPRModal`), help (`HelpOverlay`), and a detail slide-out (`TaskDetail`) for viewing full card context. Only one overlay is active at a time; Escape dismisses. The detail pane shows description markdown, remote metadata, PR branch info, and swarm step list with active step highlighted.

### Swarm controls

The web PWA supports the full user-driven swarm control surface:

**Starting a swarm.** The agents view has a "Start Swarm" flow that opens a working-directory input modal, calls `POST /api/swarm/start`, and spawns the conductor tmux session. The conductor appears in the sidebar immediately after spawn; the user can select it to watch its output.

**Plan approval.** When the conductor calls `legato swarm propose-plan`, the server broadcasts a `plan_proposed` WebSocket event to all connected web clients. Each client opens a modal showing the plan summary and sub-task list. The user can:
- **Approve** (`y`) — sends a `plan_verdict` WebSocket message with status `"approved"`; the conductor proceeds to dispatch workers.
- **Reject with notes** (`n`) — opens a text input for notes, sends `plan_verdict` with status `"rejected"`; the conductor revises the plan based on the natural-language feedback.
- **Dismiss** (`Escape`) — closes the modal without sending a verdict; the conductor remains blocked on `BroadcastRequest` and the user can re-trigger proposal from the conductor pane or TUI.

The modal does not include in-browser YAML editing (v1). Users who need surgical edits either reject with detailed notes or fall back to the TUI overlay which supports `e` to open `$EDITOR`.

**Extension plans.** When a conductor calls `legato swarm extend-plan` (or the server receives `plan_extension_proposed` over WebSocket), the modal title changes to "Extension plan — append to existing swarm". The rest of the approval flow — approve, reject with notes, dismiss — is unchanged. Web clients track whether the current modal is an extension via the `mode` field on `plan_proposed` IPC events.

**Cancel swarm.** The board detail panel (`DetailPanel.tsx`) shows a red "Cancel swarm" button when the card has active swarm stats or a working directory. Clicking it opens `CancelSwarmModal.tsx`, which confirms that the action kills the conductor + all live workers, deletes sub-tasks, and clears swarm state. The card itself and its history remain.

**Per-worker action menu.** Each agent entry in the sidebar has an overflow `⋯` button that opens a role-appropriate menu:
- **Worker** → Send message (free-text input → `POST /api/swarm/message`), Close worker (`POST /api/swarm/close`)
- **Conductor** → Send message, Finish swarm (`POST /api/swarm/finish`)

**Swarm event log.** A collapsible "Swarm events" panel appears below the terminal when the focused agent is part of a swarm. It shows unacked event entries (`#42 [progress] worker "API" — text…`) fetched from `GET /api/swarm/inbox/<parent-id>`. Clicking an entry expands the full payload. A "Drain" button calls the same inbox endpoint (which marks events acked server-side) so the user can clear them after review. Events are not auto-drained on view — multiple clients may be connected and only the active reader should ack.

**Keyboard agent switching**: Modifier key + digit (1-9) switches agents with glitch animation. `getSwitchModifier()` reads `legato:switch-modifier` from localStorage (defaults `"Alt"` on Mac, `"Control"` on Linux). Global `keydown`/`keyup`/`blur` listeners in `Agents.tsx` track `modifierHeld` state. `AgentSidebar` renders number badges when modifier held. Settings page has modifier key picker (Control/Alt/Meta).

**Draft persistence**: Per-agent text input drafts stored in localStorage (`legato:draft:<agentId>`). `PromptBar` saves draft on every keystroke, restores on agent switch, clears on submit or kill. Uses `prevAgentIdRef` + `inputRef` to handle agent switch save/load without stale closures.
