## Key Packages

- `internal/engine/store/` — Persistence boundary with a configuration-driven opener (SQLite is currently the only backend), embedded SQLite migrations, backend-neutral migration ledger/schema compatibility status, and SQLite reporting queries with store-owned range/result types. SQLite connections apply foreign keys and a bounded busy timeout per pooled connection; migration startup is serialized. The package also owns task/column mapping/sync log CRUD, task ID generation, and state interval tracking (`RecordStateTransition`, `GetStateDurations`, `GetStateDurationsBatch`, `GetStateTimeline` for sparkline bucket sequences). Production callers do not receive the raw database handle. `DeleteTask` also clears `state_intervals` for the task and any swarm sub-task children (the FK cascade was removed in migration 021)
- `internal/engine/workflow/` — Strict versioned workflow YAML parsing, legacy/XDG/project discovery, typed input normalization (including structured `task` inputs), backward-only output/artifact references, manual-step triggers, and safe prompt/input template resolution. Schema v1 also validates built-in learning executors; see [workflows](../workflows.md) and [Legato Learn](learning.md)
- `internal/engine/macros/` — Tiny shared package defining the `Macro` struct (`Name`, `Keys`) and `ListResult` JSON envelope used by the `GET /api/macros` endpoint, the TUI macro picker overlay, and the YAML config layer
- `internal/engine/events/` — Channel-based event bus with buffered pub/sub (buffer size 64, non-blocking drops on full), error event types (`EventSyncError`, `EventTransitionFailed`, `EventAuthFailed`, `EventRateLimited`) with `ErrorPayload` struct. Relevant source change events (`EventPlanChanged`, `EventWorkflowChanged`, `EventWorkflowTriggerChanged`) feed the attention service for live reconciliation; `EventAttentionChanged` with `AttentionChangedPayload` drives web/TUI inbox refresh
- `internal/engine/auth/` — Web UI auth token management. `EnsureToken(dataDir)` reads `<dataDir>/auth-token` or generates 32-byte `crypto/rand` hex token on first run. `RegenerateToken(dataDir)` overwrites with new token. `ReadToken(dataDir)` reads without generating. Token file is 0600 permissions
- `internal/engine/certs/` — Auto-generated TLS certificates. `EnsureCerts(dataDir, extraDNS...)` creates a self-signed ECDSA CA + server cert in `<dataDir>/certs/`, reuses existing if valid (not expiring within 30 days, all required DNS SANs present). Server cert SANs include localhost, loopback, all local network IPs via `net.InterfaceAddrs()`, and any extra DNS names passed in. `loadOrCreateCA` reuses existing CA across server cert regenerations. All stdlib crypto — no external dependencies
- `internal/engine/pairing/` — Pairing a phone by phrase: SPAKE2 (RFC 9382, P-256/SHA-256, checked against the RFC's vectors), the EFF short word list and `NewPhrase`, `PhraseScalar`, and `Seal`/`Open` (AES-256-GCM under a key derived from the exchange). `testdata/exchange.json` records one exchange; the app's tests must reach the same values (`go test -update` rewrites both copies). See [Web UI](web-ui.md) § Pairing by phrase
- `internal/engine/discovery/` — Announces the web server on the local network over mDNS (`_legato._tcp`), on interfaces a phone can reach only (`announceOn`)
- `internal/engine/jira/` — Jira REST API v3 client (types, HTTP client with Basic Auth/backoff, ADF-to-Markdown converter), plus `Provider` adapter
- `internal/engine/github/` — GitHub credential providers (`auto`, explicit token, or `gh auth token`) plus a GET-only HTTP client for repository PR listings, commit association, by-number refresh, reviews, checks/commit statuses, typed API errors, and rate-limit reset data. A transport guard rejects non-GET requests before dispatch; `gh` is never used for data or mutation commands.
- `internal/engine/manticore/` — Reads token usage from a Manticore instance's dashboard API (`Summary` since a time, `Hourly` buckets). GET only, no key. Feeds `service.UsageService`, which the TUI shows as tokens used today; see [TUI](tui.md) § Token usage
- `internal/engine/tmux/` — Tmux session manager: spawn, kill, capture-pane, attach, set-option, list/filter legato-prefixed sessions, `PaneCommands()` (batch query live foreground process names via `tmux list-panes -a -f`). LookPath-injectable for testing.
- `internal/service/` — LearningService (evidence-backed ledger, bounded reflection/curation, incorporation verification, prompt manifests, and drift checks; see [Legato Learn](learning.md)), WorkflowService (durable sequential runs, manual gates, typed output collection, replay-safe managed artifacts, exact-session agent cleanup, retries/cancellation, related-task attention), workflow executors (`github.pr.prepare`, `agent.run`, Yggdrasil-backed `worktree.remove`, local-only `task.note` and provider-aware `task.move`), BoardService (columns/cards CRUD + CreateTask + DeleteTask + UpdateTaskDescription + UpdateTaskTitle + UpdateTaskWorkspace + ListCardsByWorkspace + ListWorkspaces + ArchiveDoneCards + ArchiveTask + CountDoneCards), SyncService (pull/push with conflict resolution, provider→task conversion, SearchRemote + ImportRemoteTask), AgentService (tmux session lifecycle + SQLite tracking + dynamic pane command population + task title enrichment + state duration queries via `GetTaskDurations` + per-task sparkline data via `GetStateTimeline`), PRTrackingService (durable code context, repository-batched authenticated discovery, pinned refresh and targeted rediscovery), ReportService (the shared TUI/web reporting source: GenerateReport → *Report aggregating execution-bounded additive active/waiting time by day/task/workspace/swarm/directory/execution, with activity epoch and wall-clock context; Markdown export remains service-owned), AttentionService (durable high-signal registry with source-owned producers for plan decisions, workflow blockers/failures, and workflow trigger input/confirmation/failures, revision-aware dismissal, action delegation, and live event reconciliation; see `docs/ai/attention.md`), AgentUIService (what agents ask Legato to show through `legato mcp serve`: artifacts for the side panel and cards for the conversation, with the size, count and revision limits, the fixed component catalog of `show_components`, its own copies of the image files they use, and `EventAgentUIChanged`; see [Agent tools](agent-mcp.md)), `document_images.go` (the image files that the Markdown of plans and reviews names: found with `planvalidate.Images`, copied by content hash, listed, opened and swept for `PlanService` and `ReviewService`; see [Collaborative plans](../plans.md) § Image files), `AddTaskNote` (durable task notes, shared by the workflow `task.note` step and the `add_task_note` tool), `TicketProvider` interface for pluggable backends, `SeedWorkspaces` (config→DB workspace seeding)
- `internal/setup/` — Setup wizard logic: first-run column seeding, interactive Jira configuration (credential validation, project/status discovery, column mapping heuristics, config writing), `ColumnSeeder` interface for testability
- `internal/tui/` — Root Bubbletea app model, view routing (board/detail/agents/report/review/plans/attention), overlay state management (`overlayType` enum + `activeOverlay tea.Model`), registry-resolved hotkey dispatch, EventBus bridge
- `internal/tui/hotkey/` — Declarative typed hotkey registry shared by root, pages, overlays, help, and status renderers. `DefaultBindings` owns action IDs, canonical Bubble Tea keys, page/overlay/mode scopes, dispatch targets, display surfaces, ordering, capability gates, and explicit precedence; startup validation rejects duplicate/shadowed bindings. Dynamic move/workspace letters remain content-owned but query registry reserved keys before assignment
- `internal/tui/agents/` — Agents view in two layouts. The list (`list.go`): agents under what they are doing (needs you, running, background, idle, ended), the selected agent's terminal beside them, a banner when another agent needs the person (`w` selects it), capture-pane polling at 200ms. The ensemble (`grid.go`, `e`): every agent as a tile with the end of its terminal, and a record of what changed among the agents. Spawn/kill/attach/macro keybindings are shared. Under the header, a line says what the selected agent has shown through its Legato tools (cards and artifacts, which only the web UI draws) with a link to it; `o` opens the link. See [TUI](tui.md) § Agents and [Agent tools](agent-mcp.md) § In the TUI
- `internal/tui/board/` — Kanban board model with vim navigation. `view.go` lays out the title bar, the columns (a column with no cards collapses to a rail; `z` opens them) and the panel about the selected task; `column.go` and `card.go` render a column and a card with its agent strip. See [TUI](tui.md) § Board
- `internal/tui/detail/` — Full-screen task detail view with Glamour markdown, metadata header (provider-specific fields from RemoteMeta), viewport scrolling, `e` to edit Legato-owned description details via `$EDITOR` (all tasks), `t` to edit title via overlay (local tasks only)
- `internal/tui/clipboard/` — OS-native clipboard (pbcopy/wl-copy/xclip/xsel) and browser open (open/xdg-open)
- `internal/tui/overlay/` — Overlay system: shared `RenderPanel`, move overlay (single-letter shortcuts, `w` transitions to workspace assignment), search overlay (real-time filtering via `BoardService.SearchCards`), create overlay (inline task creation with title/description/column/priority/workspace), delete overlay (confirmation with remote/local distinction), import overlay (remote ticket search + import via `SyncService.SearchRemote`), title edit overlay (pre-filled text input for local tasks), workspace overlay (board view filter), move-workspace overlay (task workspace assignment), archive overlay (bulk archive done cards with count + confirmation), link PR overlay (two-phase: repo+number input → preview → confirm), help overlay (keybinding reference), agent action overlay (`Shift+M` from the agents view; role-aware Send message / Close worker / Finish swarm; routes through `SwarmService.Message`/`MessageParent`/`Close`/`Finish` via the app handlers; swarm-only — no-op for solo agents), agent spawn overlay (title, agent tool, and where the agent starts: a list of directory presets, or a typed path with suggestions; see [TUI](tui.md) § Spawning an agent), macro picker overlay (`m` from the agents view; lists `macros:` config entries and sends the chosen `Keys` payload to the focused agent's tmux pane via `SendKeysLine`/`SendKeysMultiline`)
- `internal/tui/statusbar/` — The key bar along the bottom: a message (progress, error, warning, notice), the active page's keys, and at the far end the keys marked `BarEnd`. - `internal/tui/attention/` — Attention queue model: `I` from board opens the queue, `j`/`k` navigation, `Enter` executes primary action, `D` dismisses, `q` returns to board. Refreshes on `EventAttentionChanged`
- `internal/tui/theme/` — The palette (`theme.go`), solid backgrounds for rendered blocks (`surface.go`: `Fill`, `Canvas`, `Spread`), the title bar and chips (`chrome.go`), the spinner of a running agent (`spinner.go`), and the icon system (`icons.go`: `NewIcons("unicode"|"nerdfonts")` for provider/agent/warning glyphs). See [TUI](tui.md) § Theme
- `internal/engine/ipc/` — Unix domain socket IPC: `Server` (listens, parses newline-delimited JSON, calls callback), `Send` (client, silent on missing socket), `Broadcast` (sends to all `*.sock` in `SocketDir()`), `SocketPath()` (PID-based, XDG_RUNTIME_DIR with /tmp fallback), `Message` struct (type/task_id/status/content)
- `internal/engine/hooks/` — AI tool hook script generation + swarm adapter capabilities.
  - `ClaudeCodeAdapter` implements `service.AIToolAdapter`: generates `.claude/hooks/` scripts, merges/removes `.claude/settings.json` entries. Also implements `service.LaunchCommandAdapter` (`claude --append-system-prompt "$(cat $LEGATO_ROLE_PROMPT_FILE)"` plus user `launch_args`) and `service.RolePromptingAdapter`. Does not implement `LaunchSelfKickoff` — claude needs the kickoff send-keys because `--append-system-prompt` is system context, not a user turn.
  - `ChimeraAdapter` similarly implements `AIToolAdapter`, `LaunchCommandAdapter` (`chimera --prompt "$(cat $LEGATO_ROLE_PROMPT_FILE)" [--mode <name>] [user launch_args]`), `RolePromptingAdapter`, and `RolePromptPreambleAdapter` (sandbox-mode warning prepended to every role prompt). Does implement `LaunchSelfKickoff` returning true — chimera's `--prompt` makes the role prompt content turn 1, so the agent self-starts and the kickoff send-keys is skipped. `SetModes(map[string]string)` opts into per-role `--mode <name>` injection from `cfg.Adapters.chimera.modes`; legato ships no default mode files (users opt in).
  - `CodexAdapter` implements `AIToolAdapter`, `LaunchCommandAdapter` (`codex -c developer_instructions="$(cat $LEGATO_ROLE_PROMPT_FILE)"` plus user `launch_args`), and `RolePromptingAdapter`. Like claude, codex receives the role prompt as durable developer-level context and still needs the kickoff send-keys because the brief is delivered separately. `SetNativeBridge(true)` (the default from `configuredAdapters`; `adapters.codex.native_bridge: false` opts out) makes the launch command `<legato> agent codex -- <the same arguments>` and the adapter a `service.NativeBindingAdapter`, so launch messages wait for the session's bridge. See [Codex native integration](codex-native.md).
  - `InstallClaudeMod(root)` writes the embedded Legato mod for Claude Code (`claudemod/legato/`) and `ClaudeCodeAdapter.SetModDir` makes launched sessions load it through `CLAUDE_CODE_PLUGIN_DIRS`; `LEGATO_BIN` tells the mod which binary to spawn as its bridge. With the mod set, the adapter implements `service.NativeBindingAdapter`, so messages the agent service sends at launch wait for the session's bridge instead of being typed into a tool that is still starting.
  - `InstallClaudeUsageMod(root)` writes a second embedded mod (`claudemod/manticore/`, plugin `legato-manticore`) and `ClaudeCodeAdapter.SetUsageReporting(pluginDir, url, apiKey)` makes launched sessions load it beside the bridge mod, with `LEGATO_MANTICORE_URL` and `LEGATO_MANTICORE_API_KEY` in their environment. The mod reports each model request's token counts to that Manticore instance; it is wired only when the top-level `manticore:` config block is set and does not depend on `native_bridge`. See [Claude Code native integration](claude-code-native.md) § Reporting usage to Manticore.
  - `InstallClaudeToolsMod(root)` writes a third embedded plugin (`claudemod/tools/`, plugin `legato-tools`) and `ClaudeCodeAdapter.SetToolsModDir` makes launched sessions load it. It is an ordinary plugin, not a mod: a `.mcp.json` that starts `${LEGATO_BIN} mcp serve`, a `PreToolUse` hook that allows that server's tools without a prompt, and a second one that asks `legato agent allow-read` before a `Read` that names a pasted image. `CodexAdapter.SetMCPTools` adds the same server through `-c mcp_servers.legato.*` launch overrides, and `ChimeraAdapter.SetMCPTools` through `--mcp-config` (only when `chimera --help` lists the flag). `SetToolsPrompt` on the Codex and Chimera adapters makes them a `service.ToolsPromptAdapter`, which puts the guidance about the tools in the launch prompt; Claude Code reads the server's own instructions instead. Wired by `configuredAdapters` when `agents.mcp.enabled`. See [Agent tools](agent-mcp.md).
  - `StaccatoAdapter` generates `post-pr-create` hook at `~/.config/staccato/hooks/post-pr-create/legato-pr-link.sh` (directory-based, no config file).
  - Embedded role prompts under `prompts/conductor.md` and `prompts/worker.md`; `resolveRolePrompt(overrides, role)` returns the conductor prompt for `"conductor"` and the worker prompt for any non-empty role label, honoring `SetRoleOverrides(RolePromptOverrides)` first.
  - `SetLaunchArgs([]string)` on `ClaudeCodeAdapter`, `ChimeraAdapter`, and `CodexAdapter` appends user-supplied flags to the launch command (shell-quoted via `shellQuote`).
  - `SetTiers(map[string][]string)` on `ClaudeCodeAdapter`, `ChimeraAdapter`, and `CodexAdapter` registers per-tier launch_args. `LaunchCommand(env, brief, tier)` appends the matching tier's args after the base launch_args (so tier-specified flags like `--model` win on conflicts); a `tier != ""` lookup that misses logs a warning and falls back to base args.
- `internal/engine/claudebridge/` — Per-session bridge that serves a Claude Code session to Legato in the native agent protocol Legato already speaks to Chimera: conversation state built from the Legato mod's events, snapshot + SSE replay ring, direct message/interrupt commands, held permission requests, and a lockfile for re-discovery. Hosted by `legato agent bridge`. See [Claude Code native integration](claude-code-native.md)
- `internal/engine/codexbridge/` — Per-session bridge that serves a Codex session to Legato in the same native agent protocol. It is a JSON-RPC client of the session's `codex app-server` (the terminal UI is the other client): it follows the terminal's thread, keeps the conversation as snapshot + SSE replay ring, maps Codex items to native tool calls (`bash`, `patch`) and approvals and `requestUserInput` to native permission and question requests, starts, steers and interrupts turns, holds messages sent before the terminal has a thread, and writes a lockfile for re-discovery. Self-contained, since engine packages may not import each other. Hosted by `legato agent codex-bridge`, which `legato agent codex` starts. See [Codex native integration](codex-native.md)
- `internal/engine/mcpserver/` — A stdio MCP server built from a list of tools, over the official Go SDK. It knows the protocol and nothing about Legato: `NewTool[In]` infers a tool's input schema from a Go struct (rewritten to one type per property, which model providers require) and turns a handler's error into the call's result; `Serve` runs until its client goes away. Legato's own tools are defined one layer up, in `internal/cli/mcp.go`, and served by `legato mcp serve`. See [Agent tools](agent-mcp.md)
- `internal/engine/libretto/` — Runs the libretto command, which Legato does not need to run: `Runner.Probe` asks `libretto version --json` what the installed one can do and returns `ErrNotInstalled` or a `*TooOldError` when it has no studio of level `StudioLevel`; `Explain` says what is wrong and what to do; `Runner.StartStudio` runs `libretto studio` on a storyboard, reads where it listens, and holds its input open so it ends when Legato does.
- `internal/engine/prompt/` — Reads what an agent's terminal is asking from captured pane text. `DetectForAgent` knows the approval and plan dialogs of specific tools and falls back to `detectMenu` (`menu.go`): any numbered menu with a cursor on one option, whichever tool drew it, reported as prompt type `menu` with the text above it and one action per option (the keys that move the cursor there and confirm). The web native panel shows such a menu as a card
- `internal/engine/swarm/` — File-ownership scope detection for swarm orchestration. `MatchScope(globs, path)` and `ScopeOverlaps(a, b, root)` walk the working tree and detect file-level overlaps using `github.com/bmatcuk/doublestar/v4`. Skips `.git`, `node_modules`, `vendor`, `dist`, `build`, `.next`, `.svelte-kit`, `.turbo`, `.cache`. `ValidateGlob`/`ValidateScope` reject malformed patterns
- `internal/service/resource.go` — `ResourceService`: the resources agents can be given (from the configuration and saved), resolving them by name, attaching them to running agents; the launch prompt section and the read/write grants. `agent_resources.go` holds the agent service's `AttachResources`. See [Resources](resources.md)
- `internal/service/pairing.go` — `PairingService`: the server's one pairing request (phrase, expiry, attempts), and its side of the exchange (`Exchange`, `Confirm`). In memory only. `internal/server/pairing.go` serves it; `cmd/legato/pairing_runtime.go` wires it into both web servers and starts the mDNS announcement; `cmd/legato/pair_phrase.go` is `legato pair`'s client of it
- `internal/service/directory.go` — `DirectoryService`: where an agent can be started. `Presets` (the configuration's `repositories` with a `primary_dir`, then the saved `directory_presets`), `SavePreset`, and `Suggest`, which lists the directories that complete a typed path (directories only, the one typed in full first, then presets, Git repositories, the rest; a leading `~` is the home directory). `Expand` and `Display` turn a tilde path into an absolute one and back. Built for both runtimes by `configuredDirectoryService` in `cmd/legato/directory_runtime.go`; the TUI's spawn overlay and the web spawn dialog ask it
- `internal/service/agent_conversation.go` — `AgentConversationReader.ConversationTail`: the newest things a native agent said and did, its open request and how full its context is, read from its endpoint's snapshot. The agent service implements it; the TUI's ensemble draws it. See [TUI](tui.md) § A conversation in a tile
- `internal/service/swarm.go` — `SwarmService` is the conductor-driven orchestration surface. Conductor methods: `StartSwarm`, `ApplyApprovedPlan`, `Dispatch`, `Message`, `MessageParent`, `Broadcast`, `Close`, `Finish`. Worker methods: `Progress`, `Question`, `Built`. Pending-plan persistence: `InsertPendingPlan`/`GetPendingPlan`/`ListAllPendingPlans`/`DeletePendingPlan` back the swarm-pending-plans table that survives server restarts and PWA tab suspends. `HandleAgentDied` + `StartEventLoop` subscribe to `EventAgentDied` and transition workers to `cancelled` while notifying the conductor. Per-worker progress debouncer (1s window) collapses chatty workers; `built`/`question`/`died` bypass debounce. `Snapshot(parentID)` returns JSON coordination surface; `ListSubtaskInfos` returns UI-friendly views. `LatestSnapshot(parentID)` returns a sub-millisecond in-memory `*SwarmSnapshot` (Total/Done/Cancelled/Active counters); mutated incrementally by `bumpSnapshot` on every status change path (`Dispatch`, `Built`, `Close`, `Finish`, `HandleAgentDied`, `Progress`, `Question`). On a cold cache (e.g. after a server restart), the first read lazily rebuilds from `ListSubtasksByParent` so Total/Done are correct. `ApplyApprovedPlan` re-runs `swarm.ValidatePlan` against `SwarmConfig.ValidateOptions` before persisting so the TUI/web edit-and-approve path can't bypass tier/scope checks. `internal/service/tier_catalog.go::formatTierCatalog(map[string]map[string]string)` renders the "Available tiers" markdown section that `StartSwarm` appends to the conductor brief. `AgentDiedPublisher` is a thin adapter so `agentService` can publish `EventAgentDied` without importing the events package directly. Send-keys delivery to swarm participants goes through the agent service's `Tmux()` accessor — `SendKeysLine` for short messages, `SendKeysMultiline` for multi-line payloads (auto-base64-wrapped). See `docs/ai/swarm.md` for the full lifecycle
- `internal/cli/mcp.go` — Legato's MCP tools for an agent session: `MCPServerOptions` builds the server `legato mcp serve` runs (tools listed only inside a session, each call checked against the task's running agent session), `MCPToolNames` lists them for an agent tool that must be told which calls to allow, and `MCPGuidance` is the text that tells an agent to use them without being asked.
- `internal/cli/` — CLI subcommand handlers: `TaskShow`/`TaskNotes` (full/JSON task context and durable workflow-note retrieval), `TaskUpdate` (move task to column, case-insensitive status), `TaskNote` (append timestamped note), `AgentState` (update agent activity), `AgentSummary` (tmux-formatted agent activity counts with `--exclude` flag), `AgentStatus` (swarm-aware tmux status-line markup for a single task — falls back to `AgentSummary` for solo agents; reads `state_intervals` + `swarm_subtasks` + `swarm_events` on every call since the in-process `SwarmService.LatestSnapshot` cache is unreachable from a separate CLI process), `TaskLink` (link branch/repo to task for PR tracking), `TaskUnlink` (remove PR association). All broadcast IPC to all running instances. Used by `cmd/legato/` subcommand dispatch.
- `internal/server/` — HTTP + WebSocket server for web UI. `GET /health` (unauthenticated process health and version only), `GET /api/agents` (includes a per-agent `state_timeline` field — bucket sequence over `SetSparklineWindow` window, default 10m / 10 buckets — and a native agent's last `context_used`/`context_window`, which `contextWatcher` in `agent_context.go` follows and pushes as `agent_context`; see [Web UI](web-ui.md) § Context fill, pushed), `GET /api/tasks` (legacy column-grouped board), `GET /api/report` (day/week/month ReportService view with seconds-based JSON DTO and previous-period summary, or service-owned Markdown export), `GET /api/macros` (returns the configured `macros:` list as `{"macros": [{name, keys}, ...]}`; auth-protected), `POST /api/agents/spawn` (ephemeral agent creation), `POST /api/tasks/{id}/agent` (task-bound create/resume), workflow definition/run/trigger/artifact endpoints, `GET /api/tasks/{id}/activity` (notes/reviews/plans/related runs), `POST /api/agents/kill` (ordinary agent termination; conductor IDs trigger full swarm cancellation), `/ws` (WebSocket). `SetMacros([]macros.Macro)` and `SetSparklineWindow(window, buckets)` configure the per-instance state on the `*Server` struct before `Start()`/`Serve()`. Auth middleware checks `Authorization: Bearer <token>` on API routes and `?token=` query param on WebSocket; exempt: `GET /health`, `OPTIONS`, static assets. CORS middleware sets `Access-Control-Allow-Origin: *` on all responses. `streamManager` fans out `pipe-pane` output per agent with deferred pipe start after first resize. After pipe starts, bounces pane width by 1 column to force SIGWINCH redraw through pipe (prevents snapshot/stream divergence). Output chunks sent synchronously to preserve ordering. Prompt detection via `prompt.Detect` (500ms debounce after output settles + on-demand `detect_prompt` message). `resizePane` computes min of web client sizes + attached tmux terminal clients. `send_keys` supports literal text (`\n`-terminated) and space-separated named key sequences (e.g. `"Down Enter"`). `refresh_pane` recaptures pane with ANSI escapes, restores cursor position via tmux `display-message` cursor query, and resets web xterm. Escape sequence buffering (`findIncompleteEscape`) prevents split ANSI sequences from corrupting xterm.js state. `Server.Serve(ln)` accepts pre-bound listener for auto-start use. `onStreamEnd` callback triggers `ReconcileSessions` + `agents_changed` broadcast when pipe-pane EOF detected (shell exit)

**Board endpoints.** `GET /api/board` returns the full kanban board (columns, cards, workspaces, PR metadata, swarm stats, agent state, and `agent_kind`: the agent tool a card's agents run, absent when they run different ones). `GET /api/workspaces` returns workspace configuration. `POST /api/tasks` creates a local task. `GET /api/tasks/{id}` returns card detail including durable notes (with optional `?format=full` for plain-text context export). `GET /api/tasks/{id}/activity` aggregates reviews, plans, related workflow runs, and managed artifacts. `POST /api/tasks/{id}/agent` selects/resumes a live task agent or spawns one. `PATCH /api/tasks/{id}` edits title, description, workspace, or column. `DELETE /api/tasks/{id}` removes the task. `POST /api/tasks/{id}/archive` archives a single done task. `POST /api/board/archive-done` bulk-archives all done cards. `GET /api/tasks/search?q=query` searches cards by title (min 2 chars). `POST /api/tasks/{id}/link-pr` links a task to a GitHub PR. `POST /api/tasks/{id}/unlink-pr` removes the link. `GET /api/tasks/{id}/pr-preview` fetches live PR metadata by owner/repo/number. `GET /api/repo/detect` detects the current repo from git context. `GET /api/remote/search?` searches remote tickets via SyncService (min 2 chars). `POST /api/remote/import` imports a remote ticket. Board event broadcasting via `StartBoardEvents()` subscribes to `EventCardsRefreshed`, `EventCardMoved`, and `EventCardUpdated` and broadcasts a `cards_changed` WebSocket message to all connected clients. `SetSyncService`/`SetPRTrackingService` wire optional sync and PR-tracking services respectively.

See [Web UI](web-ui.md) § Images an agent read. `POST` to the same address stores an image the person pasted into a message box, under the system's temporary directory, and answers with the path the message then names; see § Pasting an image for an agent.
- `internal/server/agent_conversation.go` — `GET /api/agents/{task_id}/conversation`: the newest things a native agent said and did, its open request and how full its context is, for a tile of the web UI's ensemble. See [Web UI](web-ui.md) § Ensemble
- `internal/server/agent_ui.go` — What agents showed: `GET /api/agents/{task_id}/ui-items` (a session's items, without content), `GET /api/ui-items/{id}[?revision=N]` (one item with its content, always inside JSON so an agent's HTML is never served as a page) and `DELETE /api/ui-items/{id}`. `GET /agent-ui-images/{task_id}/{file}` gives out Legato's copies of the image files agents showed, without a token: the address is the hash of the image's content. `document_images.go` beside it gives out the image files of plans and reviews the same way (`GET /plan-images/{folder}/{file}`, `GET /review-images/{folder}/{file}`; see [Collaborative plans](../plans.md) § Image files). `StartAgentUIEvents` forwards `EventAgentUIChanged` as the `agent_ui_changed` WebSocket message. Wired for both web servers by `wireAgentUI` in `cmd/legato/agent_ui_runtime.go`.
- `internal/server/agent_ui_studio.go` — `ANY /api/ui-items/{id}/studio/{path}`: passes a studio panel's requests on to the libretto studio of its item (started on first use by `service.AgentStudioService`), under the studio's own address and without Legato's token. Answers `503` with a `code` (`libretto_missing`, `libretto_old`) when this machine's libretto cannot serve one.
- `internal/server/swarm.go` — HTTP handlers for swarm verbs: `POST /api/swarm/start` (spawn conductor), `POST /api/swarm/dispatch`, `POST /api/swarm/message`, `POST /api/swarm/broadcast`, `POST /api/swarm/close`, `POST /api/swarm/finish`, `GET /api/swarm/status/<parent-id>`, `GET /api/swarm/inbox/<parent-id>`, `GET /api/swarm/pending-plan/<parent-id>`. All wrap `SwarmService` methods and return structured JSON (`{"status":"ok"}` or the swarm snapshot). Error responses follow the same `{"error":"<message>"}` shape as other API endpoints.
- `internal/server/ws.go` — WebSocket message types extended with swarm events: `plan_proposed` (server→client, carries plan summary + reply socket path), `plan_verdict` (client→server, carries parent task ID + status + notes + plan path), `swarm_changed` (server→client, triggers refetch of swarm status in the UI). The server subscribes to IPC `EventPlanProposed` and `EventSwarmChanged` on the event bus at startup and fans them out to all connected WebSocket clients via `hub.Broadcast`.
- `config/` — YAML config parser with env var expansion (`os.ExpandEnv`) and XDG path resolution
